# `deploy/`

Те, що крутиться на бойовому хості. Файли тут — джерело правди, але **не
автодеплой**: сервер запускає свої копії, і після зміни їх треба покласти на
місце руками. Шлях до копії — у коментарі всередині кожного файлу.

| Файл | Що це |
|---|---|
| `frontend-receiver.js` | приймає тарбол зі збіркою від Actions, розпаковує в реліз і перекидає симлінк |
| `backend-webhook.js` | оновлює чекаут API, ганяє міграції й перезапускає сервіс |
| `gunicorn.conf.py` | конфіг WSGI-сервера |
| `naverny-borschu-api.service` | systemd --user юніт API |

Обидва приймачі вимагають `WEBHOOK_SECRET` у середовищі й падають на старті,
якщо його немає. Секрети у них **різні** — у secrets репозиторію вони лежать
як `FRONTEND_WEBHOOK_SECRET` і `BACKEND_WEBHOOK_SECRET`.

Розгорнутий опис конвеєра — [../docs/deploy.md](../docs/deploy.md).
