# Як долучитися

Дякуємо. Нижче — все, що треба знати, щоб ваш PR не застряг.

Робоча мова проєкту — українська, але задачі й PR англійською теж вітаються.

## Найкорисніший внесок — це не код

Мапа живе з даних. Оцінити борщ у своєму місті на
[map.navernyborshchu.com](https://map.navernyborshchu.com) — корисніше за
більшість патчів. Особливо цінні заклади зі станом `virgin` («?» на мапі): їх
ще ніхто не куштував.

## Перед першим PR

1. Підніміть проєкт локально — [docs/local-development.md](docs/local-development.md).
2. Переконайтесь, що обидва набори тестів зелені **до** ваших змін:
   ```bash
   cd backend  && DJANGO_SETTINGS_MODULE=naverny_borschu_api.settings_test pytest
   cd frontend && CI=true npx react-scripts test --watchAll=false
   ```
3. Для помітних змін спершу заведіть issue. Прикро витратити вечір на PR, який
   не збігається з напрямком проєкту.

## Гілки

| Гілка | Куди їде | Що це |
|---|---|---|
| `develop` | [map1.navernyborshchu.com](https://map1.navernyborshchu.com) | дев-сайт на реальних даних |
| `main` | [map.navernyborshchu.com](https://map.navernyborshchu.com) | продакшн |

Робота йде **від `develop`** і мерджиться **в `develop`**. Промоушн у прод — це
окремий PR `develop → main` з людським апрувом. `main` захищений: без прямих
пушів, без force-push, і правило поширюється на адміністраторів.

```bash
git checkout develop && git pull
git checkout -b feat/коротка-назва
```

## Коміти

Conventional Commits, у теперішньому часі, тема — по суті зміни:

```
feat(map): keep markers visible when zooming out
fix(api): return place UUID after creation
docs(deploy): describe the rollback symlink
```

Префікси в обігу: `feat`, `fix`, `chore`, `docs`, `ci`, `refactor`, `test`.
Скоуп — необовʼязковий, але корисний (`map`, `api`, `flow`, `auth`, `ci`).

Тіло коміту важливіше за тему. Пишіть **чому**, а не що — «що» видно з дифу.

## Чого вимагає PR

- Зелений CI. Фронтендний білд іде з `CI=true`, тобто **будь-який ворнінг
  ESLint валить збірку**. Невикористаний імпорт — це зламаний деплой.
- Тест на кожну виправлену поведінку. Якщо баг можна було зловити тестом —
  тест має зʼявитися в тому ж PR.
- Жодних секретів, ключів і дампів. Дивіться [SECURITY.md](SECURITY.md).
- Нічого зібраного: `build/`, `staticfiles/`, `node_modules/`, `venv/`,
  `__pycache__/` у комміти не потрапляють.
- Скріншот або короткий запис екрана, якщо змінюється UI. Мобільний вигляд —
  основний: більшість користувачів приходить з телефона.

## Стиль коду

**Фронтенд.** CRA + ESLint (`react-app`). Компонент = тека з `Component.jsx` і
`Component.module.scss`. Глобальні токени й теми — `src/index.scss` і
`src/styles/`. Тексти тільки через `src/i18n/translations.js` (`uk` + `en`) —
рядок у розмітці не пройде рев'ю.

**Бекенд.** Django + DRF, стандартний PEP 8, 4 пробіли. Коментарі та
докстрінги — українською, як і решта кодової бази. Кожна зміна моделі — з
міграцією в тому ж PR.

## Пастки, на які вже наступали

Кілька речей коштували нам продакшну — не повторюйте:

- **Значення оцінок у базі — це шкала 1–10**, навіть коли інтерфейс показує
  пʼять словесних відповідей (вони мапляться 2/4/6/8/10). Не змінюйте контракт
  API заради UI.
- **Сіль немонотонна.** Похвала й маскот беруться з відповіді, не з числа.
- **Координати Google треба округлювати до 6 знаків** перед `POST /api/places/`:
  поле в базі — `DecimalField(max_digits=9, decimal_places=6)`, і «сирі»
  50.45900719999999 дають 400.
- **`100dvh` на iOS перераховується ліниво.** Висоту оболонки беремо з
  `--nb-vh`, який публікує `Layout`.
- **Поля вводу менші за 16px зумлять сторінку на iOS.** У `index.scss` стоїть
  floor 16px для `input/textarea/select` на ≤1023px — не знижуйте його.
